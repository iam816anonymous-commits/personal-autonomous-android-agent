# Phase 0 Deterministic Task Benchmark and Failure-Mode Verification Specification

**Date:** 2026-11-03  
**Workstream:** Gemini 4 Argon — Phase 0 Donor Validation (`ENGINEERING/ARGON/ARGON_DEVELOPMENT_HANDOFF.md` §2.7, §5, §6; `ENGINEERING/TEST_STRATEGY.md` §3)  
**Destination Repository:** `https://github.com/iam816anonymous-commits/personal-autonomous-android-agent`  
**Validation Branch:** `phase-0-argon-handoff`  

> **Benchmark Governance:** This benchmark defines **26 deterministic task scenarios** across all 8 required task categories in `ENGINEERING/TEST_STRATEGY.md`, plus explicit test contracts for all **14 mandatory architectural failure modes** in `ENGINEERING/ARGON/ARGON_DEVELOPMENT_HANDOFF.md` §6. No task may be scored as `PASS` based on action dispatch alone; every scenario specifies an **independent postcondition verifier** and **forbidden side effects**.

---

## 1. Benchmark Execution Rules and Scoring Contract

1. **Physical-Device vs. JVM Harness Split:**
   - **JVM/Robolectric Contract Harness (CI Gate):** Replays recorded `UiSnapshot` sequences, hardware adapter states, and fault injections (`Timeout`, `ProcessDeath`, `StaleSnapshot`, `AmbiguousSelector`, `PromptInjection`) to verify deterministic policy gating, target resolution, approval binding, and `StepVerifier` outcomes on every commit.
   - **Physical-Device Acceptance Run (Owner Gate):** Executes the live scenario on the target Android device (e.g., `TECNO IN6` API 27 and modern reference device), recording device model, OS version, build ID, elapsed time, step journal, and final independent postcondition check.
2. **Pass Criteria per Scenario:**
   - All required postconditions verified by an independent observer (`AccessibilityWindowInfo` / `UiSnapshot` with fresh `snapshotId` and `elapsedRealtimeMs`, or OS service state query).
   - Zero forbidden side effects triggered.
   - Total latency and step count within scenario timeout and budget (`MAX_STEPS <= 8`, `MAX_RETRIES_PER_STEP <= 2`, `MAX_RECOVERY_DEPTH <= 2`).

## 3. Mandatory 14-Item Architectural Failure-Mode Verification Checklist (`ARGON_DEVELOPMENT_HANDOFF.md` §6)

Every failure mode mandated in `ENGINEERING/ARGON/ARGON_DEVELOPMENT_HANDOFF.md` §6 was tested against the donor codebase (`agent-created-by-gemini` @ `90f5cf3`) and mapped to a deterministic fail-closed contract and benchmark/unit test gate for Phase 1–4:

|---|---|---|---|---|
| **1** | **Model returns an unknown action or malformed parameters** | Partial (`LocalSlmIntentEngine.validateGbnfGrammar` checks string prefixes, but `DynamicToolRegistry` allows untyped `Map<String, String>`). | Strict closed Kotlin sealed hierarchy (`AgentAction`) deserialized via `kotlinx.serialization` with schema validation; unknown action names or out-of-range parameters fail closed as `ActionValidationError.MalformedProposal` with `0` dispatches. | Unit test `ActionSchemaValidationTest` + `BM-25` |
| **2** | **Model proposes an action requiring an unavailable capability** | Partial (`DeviceCapabilityDetector` exists, but `HardwareActuatorControl` attempts calls directly and catches `Exception`). | Pre-dispatch `CapabilityRegistry.checkReadiness(capability)` verifies `(HardwarePresent, ApiLevelSupported, PermissionGranted, ServiceEnabled)`.
